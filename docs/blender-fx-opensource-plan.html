블렌더 FX 오픈소스 기획 검토

2026-09-19 · 파괴·폭발·물 시뮬레이션 애드온을 오픈소스로 만들 때의 판단

결론

세 가지(건물 파괴, 폭발, 물)를 한 번에 만들면 끝을 못 봅니다. 물리 계산기(솔버)를 새로 짜지 말고, 블렌더에 이미 들어 있는 물리를 "버튼 하나로 영화처럼 나오게" 감싸는 애드온으로 시작하세요. 첫 버전은 건물 파괴 하나만 만듭니다.

1. 먼저, 실패할 수 있는 이유

약점과 반대 근거
  1. 범위가 세 배입니다. 파괴는 "딱딱한 물건 물리", 폭발은 "연기·불 물리", 물은 "액체 물리"로 계산 방식이 전부 다릅니다. 각각이 별도 프로젝트 크기입니다.
  2. 이미 파는 물건이 있습니다. 폭발·파괴는 KHAOS(유료), 파괴 전용 RBDLab(유료), 물은 FLIP Fluids(소스 공개, 판매는 유료)가 자리 잡았습니다. "더 좋게"로는 못 이깁니다.
  3. 솔버를 직접 쓰는 건 비현실적입니다. 액체 솔버 하나가 논문급 작업입니다. 혼자 몇 달 안에 안 나옵니다.
  4. 블렌더 API가 자주 바뀝니다. 버전이 오를 때마다 애드온이 깨지는 일이 흔합니다. 유지보수가 계속 따라옵니다.
  5. 라이선스를 고를 수 없습니다. 블렌더 파이썬(bpy)을 쓰면 GPL을 따라야 합니다. 나중에 "유료 버전"으로 돌리기 어렵습니다.
  6. 시뮬레이션은 사용자 문의가 많습니다. 캐시 용량, 렌더 시간, 그래픽카드 차이로 "안 돼요"가 쏟아집니다.

2. 그래도 해볼 만한 틈새

  • 블렌더 기본 FX는 여전히 클릭 30번짜리입니다. 조각내기, 물리 켜기, 충격 주기, 먼지 붙이기, 굽기(계산 결과 저장)를 손으로 다 합니다. "버튼 하나"는 실제 수요입니다.
  • 무료로 세 가지를 한데 묶은 툴킷이 없습니다. 유료 애드온은 각자 따로 팝니다.
  • 지오메트리 노드 시뮬레이션 존(3.6+)으로 파편·먼지 같은 건 솔버 없이도 만들 수 있습니다.
  • 확장 플랫폼(extensions.blender.org, 4.2+)이 생겨서 배포와 설치가 쉬워졌습니다.
  • Sam의 시네마틱 감각이 차별점입니다. 카메라 흔들림, 먼지 타이밍, 모션블러, 파편 속도 곡선 같은 "영화처럼 보이는 마감"은 기술보다 눈이 결정합니다. 경쟁 애드온이 약한 부분입니다.

3. 무엇을 만들 것인가

항목내용
한 줄 정의블렌더 내장 물리를 영화적 프리셋으로 감싼 원클릭 FX 애드온
대상후디니 없는 1인 영상 제작자, 쇼츠·인디 필름 팀, 블렌더 초보~중급
핵심 약속"오브젝트 고르고 버튼 누르면 5분 안에 파괴 씬이 나온다"
차별점 3개① 원클릭 프리셋 ② 시네마틱 마감(카메라 흔들림·먼지·타이밍) ③ 무료·통합
안 만드는 것자체 물리 솔버, 실시간 미리보기, 게임엔진 내보내기, GPU 가속 유체

4. 단계별 로드맵

버전기간(가정)내용
v0.1파괴4~6주오브젝트 선택 → 버튼 → 조각내기 + 리지드바디 + 충격 지점 + 먼지 + 굽기. 프리셋 3개(콘크리트·유리·나무).
v0.2폭발+4주Mantaflow 연기·불 프리셋 + 힘장(밀어내는 바람) + 파편 + 카메라 흔들림. 파괴와 연결(폭발이 건물을 부순다).
v0.3물+4주Mantaflow 액체 프리셋: 컵에 붓기, 물 튀김, 파도. 해상도 3단계(미리보기·중간·최종).
v1.0공개+2주프리셋을 JSON 파일로 분리(코드 몰라도 기여 가능), 문서·데모 영상, 확장 플랫폼 등록.

기간은 주 15시간 작업 기준 가정입니다. v0.1이 끝나기 전에는 v0.2를 시작하지 않습니다.

5. 기술 구성

구분선택이유
형태파이썬 애드온, 블렌더 4.2+ 확장 형식(blender_manifest.toml)확장 플랫폼 배포 조건
파괴Cell Fracture(내장 또는 확장 설치) + Rigid Body(Bullet)검증된 내장 물리
폭발·물Mantaflow(내장 연기·불·액체)솔버 직접 구현 회피
파편·먼지지오메트리 노드 시뮬레이션 존 + 파티클가볍고 버전 안정성 높음
라이선스GPL-2.0-or-laterbpy 사용 시 필수
테스트blender --background --python 헤드리스 + GitHub Actions 버전 매트릭스(4.2 LTS, 최신)API 변경 조기 발견
배포extensions.blender.org + GitHub Releases설치 한 번에 끝

6. 첫 2주 할 일

  1. GitHub 저장소 생성, GPL 라이선스 파일, blender_manifest.toml, 빈 패널 하나 등록
  2. 오퍼레이터 1개만: 선택한 오브젝트 → 조각내기 → 리지드바디 켜기 → 바닥 충돌 → 굽기
  3. 충격 지점 지정(빈 오브젝트 하나 놓으면 거기서부터 무너짐)
  4. 먼지 파티클 자동 부착(조각 충돌 시 발생)
  5. 데모 씬 1개 렌더, 10초 영상 1개
  6. 헤드리스 테스트 1개(오퍼레이터가 오류 없이 도는지)

2주 뒤 데모 영상이 없으면 범위를 더 줄입니다. 영상이 나오면 v0.1 프리셋 3개로 확장합니다.

7. 완료 기준(무엇으로 확인하나)

  • 기능: 블렌더 초보가 설명서 없이 5분 안에 파괴 씬을 만든다(지인 2명 테스트).
  • 안정: 4.2 LTS와 최신 버전에서 헤드리스 테스트 통과.
  • 결과물: 파괴·폭발·물 각 10초 데모 영상 3개(v1.0 기준).
  • 반응: 확장 플랫폼 등록 후 첫 달 다운로드 수, GitHub 이슈 중 "안 돼요" 비율.

8. 리스크와 대응

리스크대응
블렌더 버전 오르면 깨짐지원 버전을 명시(4.2 LTS + 최신 1개). CI에서 두 버전 자동 테스트.
유료 애드온과 비교당함품질 경쟁 안 함. "무료·5분·통합" 포지션 고수. 고급 기능 요청은 이슈로 받고 거절 가능.
혼자 유지보수 지침프리셋을 JSON으로 분리해 코드 모르는 사람도 PR 가능. 이슈 템플릿에 버전·GPU·재현 파일 필수.
캐시 용량·렌더 시간 문의해상도 3단계 기본 제공(미리보기는 1분 안에). 문서 첫 줄에 권장 사양.
범위 확장 유혹v0.1 데모 영상 전까지 폭발·물 코드 금지. 로드맵 파일에 "안 만드는 것" 고정.

9. 남은 결정

  1. 프로젝트 이름과 저장소 위치(개인 계정 vs 조직)
  2. 첫 타깃: 건물 파괴로 갈지, 아니면 쇼츠 제작 흐름에 맞춰 "폭발"을 먼저 갈지. 이 문서는 파괴를 추천(내장 도구가 가장 안정적).
  3. 블렌더 최소 지원 버전: 4.2 LTS로 잡을지, 5.x 전용으로 갈지. 지금 설치된 버전 확인 필요(이번 검토 때 블렌더가 꺼져 있어 확인 못 함).
